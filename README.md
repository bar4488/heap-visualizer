# heap-visualizer

Heap allocation visualizer: renders a `.heapl` (JSONL) stream of
malloc/free/realloc events on an address-line map with two coordinated
timelines (temporal and sequential) and full time-travel.

Parsing, seeking, and rasterization happen in a Rust → WebAssembly core running
in a Web Worker with OffscreenCanvas; the page stays fully client-side.

Tag and name allocations, mark timestamps and addresses, filter the heap with
an expression language, and save the whole analysis to a `.heapa` file for
later.

## Build

Needs a Rust toolchain with `rustup target add wasm32-unknown-unknown`, Python
3, and Node.

```sh
npm install
./build.sh
./build.sh web
```

`npm install` gets `typescript` and `@types/node`; nothing ships from npm.
`./build.sh` produces `dist/`, which is generated and gitignored. `./build.sh
web` skips cargo.

## Run

```sh
./serve.py
```

Open http://localhost:8630, or `?trace=demo.heapl` to autoload the generated
demo. Drop any `.heapl` or `.heapa.json` file onto the page to load it.

The **Guide** button in the toolbar opens the built-in guide, which covers the trace format,
the map, time travel, filters, tags, and marks, with scenario traces to try
each on.

## Test

```sh
cargo test --manifest-path src/core/Cargo.toml
cargo test --manifest-path src/filter-dsl/Cargo.toml
node --test 'src/web/**/*.test.ts'
node_modules/.bin/tsc -p tsconfig.test.json
```

Engine, filter DSL, web layer, then a type-check of everything that emits
nothing. None of it needs a browser.

Rendering and pointer interaction have no automated coverage and are not going
to get any; what is checked instead, and how, is
[docs/decisions/D001](docs/decisions/D001-web-changes-are-hand-smoke-tested.md).

## Layout

- `src/core/` — Rust WASM engine (JSONL parser, columnar store, snapshot seeks,
  address-line raster, timeline binning). Plain C ABI, no wasm-bindgen.
- `src/filter-dsl/` — dependency-free Rust crate for the allocation filter
  language: source spans, syntax trees, and parsing, independent of the engine.
- `src/web/` — the viewer (TypeScript). `worker.ts` owns the WASM and canvases,
  `main.ts` is DOM chrome and input, `protocol.ts` is the message contract
  between them, `shell/` is the domain-independent window/drawer layer, and
  `heap/` is everything that knows what an allocation is.
- `dist/` — what is served. Generated by `./build.sh`, not in git.
- `gen.py` — deterministic synthetic trace generator.
- `spec/` — the specification, split into modules. Start at
  [spec/README.md](spec/README.md).
- `docs/` — how work is done here. Start at [docs/now.md](docs/now.md).
